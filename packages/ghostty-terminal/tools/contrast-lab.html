浅色主题下 PowerShell 为什么不可读

PowerShell 把语法高亮和普通输出固定打在 white(37)、brightWhite(97)、 brightYellow(93) 上——它假设自己跑在 cmd.exe 那样的深色背景里。这三个色在 seoul256-light 的 #e1e1e1 背景上对比度只有 1.03–1.16:1。下面可以逐色核对现状、 改调色板，并对照渲染层兜底的产物。兜底只作用于这十六个调色板色和默认前景——256 色立方体 与 SGR 真彩色是程序精确指定的颜色，一律原样呈现。

对比度按 WCAG 相对亮度公式计算。阈值取 3.3:1：WCAG AA 正文标准的 4.5:1（也是 VS Code 集成终端 terminal.integrated.minimumContrastRatio 的默认值）会把深色主题里 8 个色一起改掉， 观感偏离过大；3.3 只兜住真正读不出来的那几个。

兜底算法：已达标的组合原样返回；否则按背景亮度选黑或白方向，二分插值 12 次取最小改动量， 尽量保住原色相。中间灰背景两端都够不到阈值时，返回更可读的那一端。
